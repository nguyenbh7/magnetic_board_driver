# MLX90393 register and temperature-reference limits

The [Melexis MLX90393 datasheet revision 012](https://www.melexis.com/-/media/files/documents/datasheets/mlx90393-datasheet-melexis.pdf), sections 15.3 and 16, defines word-register addresses separately from their command-byte encoding: RR and WR shift the address left two bits. Decimal 24 is register `0x18` (encoded address byte `0x60`), within the documented customer free area `0x0A..0x1F`. The existing research firmware reads register `0x24` (encoded byte `0x90`), inside the Melexis area `0x20..0x3F`.

The public datasheet map does not identify the TREF address. However, the manufacturer [MLX90393 Temperature Compensation Application Note revision 4](https://www.melexis.com/-/media/files/documents/application-notes/mlx90393-temperature-compensation-application-note-melexis.pdf), page 2, identifies register `0x24` as the factory-trimmed 35 °C reference TREF, with `T = 35 + (Tdigital - TREF) / 45.2` °C. Decimal 24 (`0x18`) is not established as TREF. This corrects the H6A/H6B interpretation based only on the public datasheet map; it does not establish the installed device revision or measured accuracy. Register `0x03` is documented as two sensitivity temperature-compensation coefficient bytes, not a general temperature-offset register. The existing `temperature_offset` name should not be interpreted as a specification claim.

The installed sensor part, revision, board mapping, register readback and temperature measurement accuracy require separate physical verification. Synthetic tests do not validate field saturation, physical axes, calibration or temperature accuracy. This note changes no live address, firmware, range or conversion.
